# 第一期系统分析与设计文档 (V1.2 - Implementation Review)

## 1. 文档概述 (Overview)

### 1.1 背景与目标
本项目基于 **Astro 5 + React** 技术栈，构建了一个“自动化、风格化、高性能”的个人数字花园 (Digital Garden)。
V1.2 版本已稳步推进，核心内容管理、归档检索、以及独特的视觉风格已基本定型。目前正处于从“生存线”向“品质线”打磨的阶段。

### 1.2 现状总结
*   **已上线功能**: 首页时间轴、归档检索 (React)、文章详情渲染 (Typography)、黑白双主题 (Nanostores)、自动化部署。
*   **最近更新**:
    *   **路由逻辑重构**: 实现了物理目录多级存储与逻辑路由扁平化的分离（`content.config.ts`）。)
    *   **样式重构**: 文章正文样式抽离为独立的 SCSS 模块。
*   **待优化**: 移动端适配细节、播放器功能的深度集成。

## 2. 总体架构与技术选型 (Architecture & Stack)

### 2.1 技术栈 (Current Tech Stack)

*   **Core**: **Astro 5.0+** (SSG 模式, ClientRouter 启用 View Transitions)
*   **UI Framework**: **React 18** (用于 ArchiveApp 等强交互组件)
*   **Styling**: **Tailwind CSS v4** + **SCSS**
    *   `src/styles/global.css`: 定义 `@theme` 扩展配置与 CSS Variables。
    *   `src/styles/article.scss`: **[关键]** 专门负责 Markdown 正文的排版样式，包含亮/暗色模式下的 typography 定义。
*   **Content**: **Astro Content Collections**
    *   `glob` loader: 自动扫描 `src/content/blog`。
    *   **Flattened Slug Strategy**: 在 `content.config.ts` 中实现，忽略中间目录层级，只取顶级父文件夹作为分类。
*   **Configuration**:
    *   `src/lib/config.ts`: **[关键]** 站点配置的核心解析器。负责读取 `site.config.yaml`，提供类型安全的各种配置对象（如分类颜色、导航菜单）。

## 3. 功能模块实现详细总结 (Implementation Details)

### 3.1 M1: 内容管理与配置 (Content & Config)
*   **配置中心 (`src/lib/config.ts`)**:
    *   封装了对 `site.config.yaml` 的访问。所有关于站点元数据、分类定义（颜色、标签）、导航菜单的配置都由此文件统一输出，确保了应用配置的一致性。
*   **内容管道 (`src/content.config.ts`)**:
    *   **扁平化路由策略**: 使用自定义 `generateId` 函数。
    *   **逻辑**: 这里实现了一个特殊的映射规则——即使物理文件存储在 `src/content/blog/TECH/前端/React/hooks.md`，生成的 ID (Slug) 也会强制变为 `TECH/hooks`。
    *   **目的**: 允许作者在本地使用多级目录整理笔记，但在部署到线上时，保持 URL 的简洁 (`/posts/TECH/hooks`) 和分类的统一。

### 3.2 M2: 视觉与交互 (UI/Visuals)
*   **文章排版**:
    *   样式已从 `global.css` 迁移至 `src/styles/article.scss`。
    *   提供了 `.article-content` 类，专门处理 Markdown 生成的 HTML 标签样式，修复了列表、引用块在不同模式下的显示问题。
*   **首页时间轴**:
    *   时间轴逻辑位于 `src/lib/client/timeline.ts`，控制节点的动态加载与交互。

### 3.3 M3: 归档与检索 (Archive System)
*   **状态**: **已实现 (Implemented)**
*   **架构设计 (Hybrid Rendering)**:
    *   **构建层 (SSG/Astro)**: `src/pages/archive.astro`。
        *   负责在构建时通过 `getCollection` 获取全量文章数据。
        *   **数据清洗**: 预先计算年份、格式化日期、统计 Tag 频次、解析分类元数据 (`CategoryMeta`)。
        *   **序列化**: 将处理后的纯 JSON 数据 (`ArchivePost[]`) 作为 Props 注入 React 组件，极大减轻了客户端的计算负担。
    *   **交互层 (CSR/React)**: `src/components/archive/ArchiveApp.tsx`。
        *   一个完全受控的单页应用 (SPA) 子模块。
        *   **状态管理**: 使用 `useState` 管理 `activeCategory`, `activeTags`, `searchKeyword`。
        *   **副作用控制**: 两个核心 `useEffect` 分别负责 "URL -> State" (初始化/后退) 和 "State -> URL" (操作反馈) 的双向同步。
*   **核心逻辑**:
    *   **Deep Linking (深度链接)**: 所有的筛选状态（分类、多标签、关键词）都透传至 URL Query Parameters (e.g. `?category=tech&tag=react&tag=hooks`)。用户刷新页面或分享链接时，能完美还原当前的筛选视图。
    *   **复合过滤 (Multi-dimensional Filtering)**:
        *   采用 `AND` 逻辑组合：`(Category Match) && (All Tags Match) && (Keyword Match)`。
        *   使用 `useMemo` 缓存过滤结果和年份分组计算，确保在输入搜索词时的高频渲染下保持流畅。
    *   **交互细节**:
        *   **Tag Wall**: 搜索框聚焦或输入 `#` 时弹出标签墙，按频次降序排列，支持键盘导航。
        *   **Visual Feedback**: 列表行悬停时展示分类色左边框；移动端优化了触摸区域。
*   **实现链路 (Implementation Chain)**:
    1.  **构建阶段 (Build Time)**:
        *   `archive.astro` 执行 `await getCollection('blog')`。
        *   调用 `utils.ts` 中的 `getCategoryMeta` 解析分类颜色。
        *   生成 `posts`, `categories`, `tags` 三大核心数据结构。
    2.  **客户端激活 (Hydration)**:
        *   React 组件挂载 (`client:only="react"`)。
        *   `useMemo` 读取 `window.location.search`，初始化内部 State。
    3.  **交互循环 (Interaction Loop)**:
        *   用户点击 Tag / 切换 Tab -> `setActiveTags` / `setActiveCategory`。
        *   `useEffect` 监听到 State 变化 -> 调用 `history.replaceState` 更新 URL（不刷新页面）。
        *   `useMemo` 依赖 State 变化 -> 重新计算 `filteredPosts` -> 触发 Virtual DOM Diff -> 更新视图。

### 3.4 M4: 全局媒体播放 (Global Media Player)
*   **状态**: **已实现 (Implemented)**
*   **架构设计**:
    *   **UI 层**: `src/components/player/GlobalPlayer.tsx` (React)。
        *   负责渲染播放控制条、专辑封面动效、以及歌词面板。
        *   实现了基于 Touch 事件的 **Swipe 手势控制** (左滑上一曲/右滑下一曲)。
        *   **交互细节**: 专辑封面加载时的骨架屏、播放时的声波动画、歌词面板的淡入淡出。
    *   **逻辑层**: `src/lib/client/playerBridge.ts`。
        *   实现了 **Player Bridge 模式**，将 HTMLAudioElement 的原生事件封装为统一的业务逻辑。
        *   **歌词解析**: 内置 LRC 解析器，支持从 URL 异步加载歌词或解析内嵌文本，并实现了精确到毫秒的时间轴同步 (`syncLyricByTime`)。
        *   **资源加载**: 支持标准 Meting 格式的 JSON 接口，自动规范化字段。
    *   **状态层**: `src/stores/player.ts` (Nanostores)。
        *   作为全局单例状态源，实现了组件间（如文章页点击播放 -> 全局播放器响应）的解耦。
*   **实现链路 (Implementation Chain)**:
    1.  **初始化**: `GlobalPlayer` 组件挂载 -> 调用 `initPlayerBridge`.
    2.  **数据获取**: Bridge 请求 `source.playlistApi` -> 获取 JSON -> 规范化为 `TrackInfo[]`.
    3.  **播放控制**: 用户点击 Play -> Store 更新 `$isPlaying` -> Bridge 监听到状态变化 -> `audio.play()`.
    4.  **歌词同步**: `timeupdate` 事件 -> `findLyricFrame` 查找当前行 -> `onLyricFrame` 回调 -> React State 更新 -> UI 渲染.

### 3.5 M5: 自动化运维与双仓架构 (DevOps & Dual-Repo)
*   **双 Git 仓库设计**:
    *   **Code Repo**: `sounfury/Echoes` (本项目) - 存放 Astro 源码、构建脚本、样式。
    *   **Content Repo**: `sounfury/blog` (私有/公开) - 纯 Markdown 写作库，文件夹结构即分类。
*   **CI/CD 流程 (Implementation Chain)**:
    1.  **触发 (Trigger)**: 作者在 `blog` 仓库 Push 代码 -> GitHub Webhook 触发 `repository_dispatch` 事件。
    2.  **构建 (Build)**:
        *   Workflow: `.github/workflows/deploy-oss.yml`.
        *   **Checkout**: 同时检出 Code Repo (主分支) 和 Content Repo (指定 SHA)。
        *   **Sync**: 使用 `rsync` 将 Content Repo 中的一级目录（如 `TECH`, `LIFE`）同步至 `src/content/blog/`。
        *   **Flatten**: Astro 构建时，`content.config.ts` 将多级物理目录映射为扁平路由。
    3.  **部署 (Deploy)**: `pnpm build` -> 生成静态文件 -> `aliyun-oss-website-action` 上传至 OSS Bucket。
    4.  **通知 (Notify)**: Python 脚本解析事件并生成 Bark 通知推送到作者手机。
        *   **成功通知**: 解析 `changed_files` 生成具体文章链接或批量成功消息。
        *   **失败告警**: Workflow 通过 `if: failure()` 捕获构建或部署错误，设置 `NOTIFY_STATUS=failure` 触发专用的失败通知模板，并可通过配置 `url` 固定跳转到 GitHub Actions 页面查看日志。

### 3.6 M6: SEO 基础设施 (SEO Infrastructure)
*   **状态**: **已实现 (Implemented)**
*   **架构设计**:
    *   **配置层**: `site.config.yaml` 中 `site.description` 提供独立的站点描述，与 `subtitle`（副标题/slogan）分离。
    *   **Meta 标签**: `BaseLayout.astro` 通过 `astro-seo` 统一输出 `<meta name="description">`、OpenGraph (`og:title`, `og:description`, `og:site_name`, `og:locale`, `og:image`) 和 Twitter Card (`twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`)。
    *   **Sitemap**: `@astrojs/sitemap` 集成，构建时自动生成 `sitemap-index.xml`。
    *   **Robots.txt**: `astro-robots-txt` 集成，构建时自动生成 `robots.txt`，包含 sitemap 引用。
    *   **OG Image**: 默认 OG 图片位于 `public/covers/og-default.jpg`。
    *   **结构化数据**: 文章页通过 JSON-LD 输出 `BlogPosting` schema（headline、author、datePublished、dateModified、keywords）。
    *   **摘要提取**: `getExcerpt()` 公共函数（`utils.ts`），从 Markdown 正文提取第一个非空非标题段落前 120 字，供时间轴和文章页 SEO 复用。
*   **各页面 description 策略**:
    *   **首页 `/`**: 使用 `site.description`（全局默认）。
    *   **归档页 `/archive`**: 专属描述："按分类与标签检索所有文章 — Echoes 归档数据库"。
    *   **文章页 `/posts/*`**: 使用 `getExcerpt()` 从正文自动提取摘要。
