# Echoes 评论系统接入说明

## 1. 背景

本次为 Echoes 博客接入评论系统，目标是：

- 尽量保持弱后端；
- 不要求读者必须拥有 GitHub 账号；
- 评论入口与现有 Astro 文章页自然融合；
- 保留后续继续增强审核、通知和身份能力的空间。

最终选择为：

- 前端：`@waline/client`
- 评论服务：已部署的 `https://comments.sounfury.top`
- 主站接入方式：文章页底部按页面路径挂载评论区

---

## 2. 本次落地范围

### 2.1 已完成

- 在文章详情页底部接入 Waline 评论区；
- 新增站点级评论配置项；
- 接入 `comments.sounfury.top` 作为评论服务地址；
- 采用邮箱必填的游客评论模式；
- 开启可选登录能力，便于站长以管理员身份发表评论；
- 为评论区补充站点风格样式；
- 增强昵称与计数显示逻辑：
  - 邮箱输入后自动生成脱敏默认昵称，用户可手动覆盖；
  - 评论框计数显示按非空白字符统计，避免英文输入统计失真。

### 2.2 本次未做

- 不强制所有访客登录；
- 不接入图片上传；
- 不接入浏览量统计；
- 不接入评论通知邮件；
- 不额外实现自定义审核后台。

## 4. 当前配置说明

当前 `src/config/site.config.yaml` 中的评论配置如下：

```yaml
comment:
  enabled: true
  serverUrl: https://comments.sounfury.top
  lang: zh-CN
  meta:
    - nick
    - mail
    - link
  requiredMeta:
    - nick
    - mail
  login: enable
  pageSize: 10
  reaction: false
```

配置语义：

- `enabled`
  - 是否启用评论区
- `serverUrl`
  - Waline 服务端地址
- `meta`
  - 评论表单展示的字段
- `requiredMeta`
  - 必填字段，当前为昵称和邮箱
- `login: enable`
  - 访客可直接评论，同时支持站长登录 Waline 账号后以登录身份发表评论
- `pageSize`
  - 每页评论数量
- `reaction`
  - 文章反应功能，当前关闭

## 5. 关联方式

评论与文章的关联方式不是文章数据库主键，而是**页面路径**。

当前实现中，文章页会把：

- `Astro.url.pathname`

作为 `path` 传给 Waline。

这意味着：

- 每篇文章的评论独立挂在对应 URL 路径下；
- 如果文章 slug 未来发生变化，Waline 会把新路径视为新的评论线程；
- 测试文章的评论不会跑到正式文章下，但如果测试文章删除，对应评论会留在评论数据库中。

## 6. 当前身份策略

### 6.1 访客评论

当前仍允许游客评论，但要求：

- 昵称必填；
- 邮箱必填。

注意：

- 这属于弱身份，不等于邮箱验真；
- 用户仍然可以填写假邮箱；
- 只是比“纯昵称模式”多一层约束。

### 6.2 默认昵称生成

当用户输入邮箱而昵称为空时，前端会自动生成一个**脱敏默认昵称**。

示例：

- `alice@example.com` 可能生成 `al***ce`

规则：

- 仅在昵称为空或仍是上一次自动生成值时自动覆盖；
- 一旦用户手动修改昵称，后续不会再被自动昵称强制覆盖。

### 6.3 站长身份

Waline 的“管理员/站长身份”依赖登录用户身份，而不是手填昵称。

当前站长显示身份的方式为：

1. 保持 `login: enable`
2. 访问 `https://comments.sounfury.top/ui/register` 或 `https://comments.sounfury.top/ui/login`
3. 使用 Waline 管理员账号登录
4. 回到前台文章页发表评论

说明：

- Waline 官方默认规则中，第一个注册用户会成为管理员；
- 登录后的评论可以显示管理员身份；
- 可在 Waline 管理端继续为该账号设置专属标签，例如“站长”或“博主”。

## 7. 当前已知行为

### 7.1 头像来源

当前评论头像并非站内生成。

根据已有接口返回结果，现阶段服务端会为纯数字昵称返回 QQ 头像地址，例如：

- `12345 -> https://q1.qlogo.cn/g?b=qq&nk=12345&s=100`

因此：

- 纯数字昵称会出现类似 QQ 头像的效果；
- 该逻辑来自 Waline 服务端或其头像配置，而非博客前端。

### 7.2 字数统计

Waline 默认更偏向“词/字”统计，英文输入时反馈不直观。

本次已在前端显示层做调整：

- 改为按非空白字符统计；
- 英文、数字、中文都会逐字符累计；
- 仅修正前端显示反馈，不改动 Waline 包本身。

### 7.3 登录与访客共存

当前为 `login: enable`，因此：

- 普通访客可以不登录直接评论；
- 站长可以登录后以管理员身份评论；
- 没有切到 `force`，不会强制所有访客注册或登录。

## 8. 一次问题记录

在增强“邮箱自动补昵称”和“字符计数显示”时，曾出现进入文章页浏览器卡死的问题。

原因是：

- 评论区增强逻辑使用了 `MutationObserver`；
- 观察器在监听 DOM 变化的同时又修改了计数文本；
- 文本更新继续触发新的 DOM 变化，形成高频循环。

已修复为：

- 仅在评论面板结构变化时触发同步；
- 字数文本只有在发生实际变化时才更新；
- 邮箱为空时不再自动写入昵称。

## 10. 后续建议

建议按优先级逐步补齐：

1. Waline 管理端中为站长账号设置专属标签；
2. 开启评论审核或完善审核策略；
3. 配置评论通知邮件；
4. 视需要决定是否切换为更强身份模式：
   - 保持游客评论；
   - 强制登录；
   - 或后续迁移到更深度的自建身份体系。
