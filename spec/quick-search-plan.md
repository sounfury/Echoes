# Echoes Quick Search / Command Palette 实施计划

## 1. 背景与目标

基于 `spec/博客prd文档.md` 的最新定义，导航栏搜索入口不再承担 Archive 页的复合检索职责，而是收敛为一套轻量、全局可呼出的 **Quick Search / Command Palette**。

该能力的目标是：
- 在任意页面中快速查找文章并直接跳转；
- 提供页面级快捷入口（Timeline / Archive / Universe）；
- 通过 `⌘K / Ctrl+K` 提升键盘用户效率；
- 与 Archive 页“高级搜索 / 复合筛选”形成明确分工。

---

## 2. 范围定义

### 2.1 本期纳入范围（MVP）
- 点击导航栏搜索图标打开悬浮搜索框；
- 支持 `⌘K / Ctrl+K` 呼出、`Esc` 关闭；
- 支持文章标题搜索；
- 支持标签作为辅助匹配条件；
- 支持固定页面入口搜索（Timeline / Archive / Universe）；
- 支持上下方向键切换、Enter 打开；
- 支持空状态展示最近文章或快捷入口；
- 支持“前往 Archive 高级搜索”入口。

### 2.2 明确排除范围
- 不支持 Tag Chip；
- 不支持 `#` 标签墙；
- 不支持多 Tag 复合筛选；
- 不支持 Archive 级别高密度列表承载；
- 不新增独立搜索结果页。

---

## 3. 信息架构与交互设计

## 3.1 入口
- Header 搜索按钮；
- 键盘快捷键 `⌘K / Ctrl+K`；
- 后续可选增加 `/` 唤起，但不作为本期必做。

## 3.2 弹层结构
1. 顶部：搜索输入框；
2. 中部：结果列表；
3. 底部：交互提示与 Archive 跳转入口。

## 3.3 结果分组建议
- `Posts`
- `Pages`

## 3.4 单条结果建议展示字段
- 标题；
- 日期（文章）；
- 分类或 1~2 个标签；
- 当前命中字段高亮。

## 3.5 空状态
建议展示：
- 最近 5 篇文章；
- 或 3 个快捷入口：Timeline / Archive / Universe。

## 3.6 无结果状态
展示：
- `NO MATCHING RESULTS`
- `Go to Archive for advanced search`

## 4. 技术实现拆分建议

## 4.1 推荐新增文件
- `src/components/search/QuickSearch.tsx`
- `src/components/search/types.ts`
- `src/lib/search.ts`
- 如需拆分客户端控制：`src/lib/client/quickSearch.ts`

## 4.2 推荐修改文件
- `src/components/common/Header.astro`
  - 将当前直接跳转 `/archive` 的搜索 icon 改为打开 Quick Search；
  - 保留前往 `/archive` 的深度入口，由面板底部提供。
- `src/layouts/BaseLayout.astro`
  - 挂载全局搜索组件，保证任意页面可唤起；
  - 如使用 View Transitions，需要确认事件绑定不会重复注册。

## 4.3 数据来源
优先复用现有内容集合输出的轻量元数据：
- `title`
- `slug`
- `date`
- `category`
- `tags`
- `description` / `summary`（若已有）

页面项可静态定义：
- `/`
- `/archive`
- `Universe` 外链

## 4.4 搜索策略
MVP 采用轻量前端匹配：
- 标题命中：最高权重；
- 标签命中：中权重；
- description 命中：低权重；
- 页面名命中：高权重。

排序建议：
1. 完整前缀匹配；
2. 标题包含；
3. 标签包含；
4. 描述包含；
5. 日期新的文章优先。

如后续内容量显著增长，可升级到 Fuse.js 或预构建搜索索引。

## 6. 风险与注意事项

### 6.1 功能边界漂移
风险：开发过程中不断往 Quick Search 增加 Tag Wall、复合筛选，最终与 Archive 重叠。

控制策略：
- PRD 中明确“Quick Search 只负责快速直达”；
- 复杂筛选统一回收至 Archive。

### 6.2 事件重复注册
风险：Astro View Transitions 下，页面切换后快捷键事件或点击事件重复绑定。

控制策略：
- 所有全局监听在初始化前先清理旧实例；
- 或通过单例标识防止重复注册。

### 6.3 移动端体验不稳定
风险：桌面浮层方案直接照搬到移动端，导致输入区域拥挤。

控制策略：
- Mobile 使用全屏层，不强行沿用桌面宽浮窗。

### 6.4 搜索结果质量不足
风险：简单 includes 匹配导致排序不够合理。

控制策略：
- 先用权重排序补足；
- 如后续内容规模扩大，再升级模糊搜索方案。
