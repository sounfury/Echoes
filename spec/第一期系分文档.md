# 第一期系统分析与设计文档 (V1.1 - Implementation Review)

## 1. 文档概述 (Overview)

### 1.1 背景与目标
本项目基于 **Astro 5 + React** 技术栈，构建了一个“自动化、风格化、高性能”的个人数字花园 (Digital Garden)。
V1.1 版本已完成核心生存线 (P0) 与体验差异化 (P1) 需求，实现了从 Markdown (Obsidian) 到 Web 的静态发布流、独特的 EVA 风格时间轴视觉、以及响应式的归档检索系统。

### 1.2 现状总结
*   **已上线功能**: 首页时间轴、归档检索 (React)、文章详情渲染 (Typography)、黑白双主题 (Nanostores)、自动化部署 (Aliyun OSS + Bark 通知)。
*   **待优化**: 移动端适配细节、部分交互溢出问题。

## 2. 总体架构与技术选型 (Architecture & Stack)

### 2.1 技术栈 (Current Tech Stack)

*   **Core**: **Astro 5.0+** (SSG 模式, ClientRouter 启用 View Transitions)
*   **UI Framework**: **React 18** (用于 ArchiveApp 等强交互组件)
*   **Styling**: **Tailwind CSS v4**
    *   `src/styles/global.css`: 定义 `@theme` 扩展配置与 CSS Variables。
    *   `@tailwindcss/typography`: 渲染 Markdown 正文。
*   **State Management**: **Nanostores** (`@nanostores/react`)
    *   `theme.ts`: 管理全局主题模式 (light/dark)。
*   **Content**: **Astro Content Collections**
    *   `glob` loader: 自动扫描 `src/content/blog`。
    *   **Custom generateId**: 自定义 ID 生成逻辑，保留中文文件名作为 Slug（解决 Url Encode 问题）。
*   **Deployment**: **GitHub Actions** -> **Aliyun OSS**
*   **Notification**: **Python Script** (调用 Bark POST 接口)

### 2.2 实际目录结构

## 3. 功能模块实现详细总结 (Implementation Details)

### 3.1 M1: 内容管理与配置 (Content & Config)
*   **配置中心**: `src/config/site.config.yaml` 集中管理站点信息、主题色、导航菜单与 Bark 推送模板。`src/lib/config.ts` 提供类型安全的读取接口。
*   **内容管道**:
    *   使用 `src/content.config.ts` 定义 `blog` 集合。
    *   **关键实现**: 自定义 `generateId` 回调，`entry.replace(/\.(md|mdx)$/, '')`，确保中文文件名不被 `github-slugger` 转义或过滤，保证了 URL 的可读性和标题生成的准确性。

### 3.2 M2: 视觉与交互 (UI/Visuals)
*   **主题系统**:
    *   **实现**: CSS Variables (`--c-bg`, `--c-accent` 等) + Tailwind v4 `@theme` 配置。
    *   **切换逻辑**: `BaseLayout` 中注入 Inline Script 防止 FOUC (Flash of Unstyled Content)。`theme.ts` store 负责组件间状态同步与持久化。
    *   **EVA 风格**: 大量使用等宽字体 (JetBrains Mono)、高对比度线条、以及装饰性的系统状态文本。
*   **首页时间轴**:
    *   **实现**: `Timeline.astro` 使用 CSS Grid 布局。
    *   **视觉**: 中心轴线贯穿，节点通过 `border` 和 `before` 伪元素绘制。根据文章分类 (`tech`, `review`, `life`) 动态渲染不同的图标。
    *   **加载策略 (2026-02-24 更新)**:
        *   首屏默认加载数量改为配置驱动：`src/config/site.config.yaml` 中 `timeline.pageSize`（默认 `5`）。
        *   滚动到底部仅触发一次自动加载（再加载 `pageSize` 条）；后续加载统一由 `[ Load More Data ]` 按钮触发。
        *   跨页面返回首页时，时间轴通过 `sessionStorage` 恢复已加载数量与“自动加载是否已触发”状态，避免已加载数据回退失效。

### 3.3 M3: 归档与检索 (Archive System)
*   **架构**: 纯客户端 React 应用 (`src/components/archive/ArchiveApp.tsx`)，挂载在 `archive.astro` 页面中。
*   **功能点**:
    *   **双向同步**: URL 参数 (`?category=tech&tag=docker`) 与组件状态双向绑定，支持刷新保持状态。
    *   **交互式筛选**: 支持 Category Tab 切换、Tag 点击移除。
    *   **复合搜索**:
        *   输入框支持普通关键词 (Title/Tag 模糊匹配)。
        *   **Tag Wall**: 输入 `#` 或聚焦时弹出标签墙，展示 Tag 统计计数。
    *   **视图**: 按年份分组的高密度列表视图，悬停高亮当前行及对应的分类色。

### 3.4 M4: 媒体播放 (Media - Phase 2 Pending)
*   目前仅预留了 `src/stores/player.ts` 状态定义。具体播放器组件与 Meting 集成将在 P2 阶段实施。

### 3.5 M5: 自动化运维 (DevOps)
*   **GitHub Actions**: `.github/workflows/deploy-oss.yml`。
    *   执行 `pnpm build`。
    *   使用 `fangbinwei/aliyun-oss-website-action` 将 `dist/` 部署至阿里云 OSS。
*   **智能通知 (Bark)**:
    *   **Python 脚本**: `scripts/notify.py` (无第三方依赖)。
    *   **Git Diff**: 对比 `github.event.before` 与 `github.sha`，精确检测 Markdown 变更。
    *   **模板消息**: 根据变更数量（0, 1, N）匹配 `site.config.yaml` 中的不同模板。
    *   **跳转优化**: 单篇文章发布时，通知包含 `url` 参数，支持点击直接跳转至博文页。

## 4. 当前不足与待优化 (Issues & Improvements)

### 4.1 移动端适配问题
*   **导航栏溢出**: Header 的汉堡菜单 (Hamburger Menu) 在展开时，如果菜单项过多或屏幕过短，会出现内容溢出无法滚动，或者背景模糊层遮挡层级异常的问题。

### 4.2 构建与部署
*   **Git 路径转义**: 之前遇到的 Git 输出中文文件名被八进制转义的问题，已通过 `core.quotePath=false` 修复，但需注意不同 CI 环境的 Git 版本差异。

### 4.3 性能
*   **搜索性能**: 当前 Archive 页是全量加载文章元数据。随着文章数量增长到 100+，需要引入 `Pagefind` 进行真正的静态索引搜索，以减小初始 bundle 体积。

### 4.4 ui

*   **搜索按钮**: 搜索按钮点击后直接跳转到 Archive 页，与 Archive 页搜索功能重复了，是否要删除或是定义新功能?
