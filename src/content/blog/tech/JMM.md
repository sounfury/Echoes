JMM就是Java Memory Mode也就是Java内存模型。JMM是一种并发编程的规范，并不是具体实现(注意)。JMM定义了JVM虚拟机和计算机内存(RAM)的工作方式。把内存分成主内存以及工作内存，主内存就是计算机内存(RAM)，工作内存就是缓存。


![image.png](https://sounfury-image.oss-cn-beijing.aliyuncs.com/%E5%8D%9A%E6%96%87/20251119155749744.png)


并且规定操作一个变量的时候不能直接在主内存里面去改，因为直接在主内存里面去改性能比较低，所以操作共享变量的时候首先得把共享变量复制一份放到工作内存里面，因为在工作内存里面进行操作的话性能是比较高的。操作完了之后还要保证必须把操作这个共享变量刷新到主内存里面让其他的CPU能够看到共享变量的修改。**其实就是规范了一个线程如何以及何时可以看到其他线程修改过的共享变量的值，以及在必要时如何同步访问共享变量。**

## JMM解决了什么问题?
+ 可见性->更改共享变量其他线程也能看见
+ 有序性->保证指令不被重排
+ 原子性->i++这种非原子操作如果其他线程插手怎么办？ ->可以使用synchronied等锁来解决

volatile能保证可见性（禁用cpu缓存，必须从主存里面去读 ）和有序性（**通过插入内存屏障**，禁止指令重排序），但是无法保证原子性



## happens-before规则
对同一把锁的 `unlock`（monitor exit） happens-before 之后的 `lock`（monitor enter）。
含义：

- 线程 A 在退出同步块前，对共享变量的写入必须刷回主内存（释放语义）。
    
- 线程 B 进入同步块时，必须从主内存重新读取共享变量（获取语义）。
    
- 所以 B 看到的是 A 在 unlock 前的所有写。


核心思想是指定一系列操作的顺序保证，确保在一个线程对共享变量的写操作能够在另一个线程读取时看到。这个规则主要通过以下几种方式实现：
1. **程序顺序规则（Program Order Rule）**：
    
    - 一个线程中的操作总是按照它们在程序中出现的顺序发生。
        
    - 例如，如果在同一个线程中执行 `a = 1; b = 2;`，那么 `a = 1` 的操作必定在 `b = 2` 之前发生。
        
2. **监视器锁规则（Monitor Lock Rule）**：
    
    - 一个线程释放一个锁时，所有其他线程在获得同一个锁之前，必须看到该线程对共享变量的所有修改。
        
    - 例如，线程 A 在同步块中执行了 `lock` 和 `unlock`，而线程 B 获取到相同的锁后，它能看到线程 A 之前对共享变量的修改。
        
3. **volatile变量规则（Volatile Variable Rule）**：
    
    - 对 `volatile` 变量的写操作总是发生在后续所有对该变量的读操作之前。
        
    - 如果一个线程写入了一个 `volatile` 变量，其他线程对该变量的读操作必定能看到这个写操作的结果。
        
4. **传递性规则（Transitivity Rule）**：
    
    - 如果 `A happens-before B` 且 `B happens-before C`，那么 `A happens-before C`。
        
    - 这是为了保证多个线程间操作顺序的一致性。
        
5. **线程启动规则（Thread Start Rule）**：
    
    - 当一个线程调用 `start()` 方法启动另一个线程时，所有在启动线程之前的操作必须在新线程开始执行之前发生。
        
    - 例如，线程 A 调用了线程 B 的 `start()` 方法，线程 A 中的操作会在线程 B 开始执行之前发生。
        
6. **线程终止规则（Thread Termination Rule）**：
    
    - 当一个线程调用另一个线程的 `join()` 方法时，调用线程必须等到被 `join` 的线程执行完毕之后才能继续执行。
        
    - 例如，线程 A 调用线程 B 的 `join()` 方法，线程 A 必须等到线程 B 完全执行完之后，才能执行后续操作。
